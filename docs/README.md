## 如何维护这套文档

- 代码行为变化时，同一任务更新对应专题；从导航索引链接到专题，不复制大段说明到多处。
- 项目上下文保留概览；完整路由归架构，字段与发布流程归内容专题，测试与部署命令归开发专题。
- 写清“当前实现”“内容约定”“建议改进”的区别。未运行的命令不能记为通过，静态疑点不能记为已复现故障。
- 涉及数量、文件大小、版本、源码基线或历史验收时注明日期；不要把快照写成永久约束。
- 源码路径使用仓库相对链接；不要新增只在某台电脑有效的截图、日志或临时目录引用。
- 不将 API 凭据、专属服务配置值或私有运行产物复制进说明。
- 修复问题后更新问题条目的状态与实际验证，避免旧问题长期与实现不符。

文档不替代源码。若发现冲突，先核对实际代码和验证结果，再同步修正文档与相关索引。
